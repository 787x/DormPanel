# PR19 dual brightness and HA Blackout

System brightness and DormPanel brightness have separate owners. `AndroidSystemBrightnessPort` reads and writes Android `Settings.System` only after `canWrite` grants special access. `DeviceControlController` owns the writable state and commands; Control Center only displays that state and sends intent. `MainActivity` observes both Settings brightness keys with a `ContentObserver` and refreshes the permission and mode on resume. No background polling is used.

The connected X08E reports `mScreenBrightnessRangeMinimum=1` and `mScreenBrightnessRangeMaximum=255` through `dumpsys display` on Android 9. User percentages 1–100 map linearly and deterministically to raw 1–255. Automatic mode disables the System slider. Only an explicit Automatic toggle changes the global mode. The System HA helper accepts commands only while the controller observes manual mode and write access. Ambient automatic changes update Control Center but are not mirrored to HA.

DormPanel's saved `brightness` remains the last local Window override. The new `follow_system` preference defaults to true when legacy `brightness` is absent and false when it exists. Follow System sets Window brightness to `-1f`; switching it off reapplies the saved value. A valid HA DormPanel brightness event establishes an override. Reconnect snapshots leave Follow System active. Blackout stays a true-black overlay with 1% Window brightness, never a screen power command. It is not saved locally; a configured, connected HA `input_boolean` can apply its authoritative startup state. Any touch down on the overlay exits locally, regardless of HA service success.

HA configuration retains `display_brightness` as the DormPanel helper. New `system_brightness` and `blackout` settings are optional. A connected system-helper snapshot is considered only while manual mode and write access are both present; it never switches Automatic off. Number helper slider traffic uses the existing latest-wins command queue; Blackout uses explicit `input_boolean.turn_on` and `turn_off`. Local events do not echo back to HA when the same state is observed.

Physical X08E checks on 25 September 2026 used only `com.dormpanel.app.testbed`. `ACTION_MANAGE_WRITE_SETTINGS` opened `com.android.settings/.Settings$AppWriteSettingsActivity`, showing a working "Allow modifying system settings" switch for DormPanel Testbed. After grant and return, Control Center's read-only action disappeared and its Automatic toggle enabled without a process restart. A granted instrumentation test set 100%, 50%, and 10% in manual mode and restored the original mode and value in `finally`. UI slider taps yielded raw Settings values 252, 129, 27, and 152 at positions near 100%, 50%, 10%, and 60%. With global raw 152, the DormPanel 20% override produced display-service brightness 51 and `mAppliedScreenBrightnessOverride=true`. After the display ramp settled, MIUI Home and DormPanel in Follow System each reported `mBrightness=152` and `mAppliedScreenBrightnessOverride=false`. The raw Settings value remained 152 until restoration.

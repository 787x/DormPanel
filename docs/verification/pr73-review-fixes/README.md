基线 f17e747，只更新原 PR73。未改持久化、同步协议、WebDAV 或同步快捷按钮；未升级日用 APK。独立滚动及无关功能复用已有证据。

## 选择日期

共用日期栏明确区分两种模式：日视图蓝底跟随选中日期且没有小圆点；周视图蓝底仍是今天，选中非今天恢复“·”。今天始终保留“●”，选中今天不额外添加小点。只增加 weekView 条件，不改变日期切换逻辑。

Android 定向测试先选中本周另一天，核对日视图蓝底／无小点及今天大点，再切周视图核对今天蓝底／另一天小点，随后选中今天确认无额外小点，最后切回日视图。API 28 和 MIUI API 33 各通过 1 项。

## 教学周参与范围

只读使用正式有效投影中“今天未结束课程＋明天全部课程”的来源。每个相关来源必须存在且能够解析学期；本地课程没有来源学期关联时不借用其他导入源的配置。全部相关来源必须引用同一个学期键，且配置键与 profile.termKey 一致、validate 有效、时区匹配、今天明天均存在有效阶段，计算出的周数为正。

多个来源引用同一个有效学期允许显示；缺少关联、未知来源、无效／缺失配置和冲突学期留空。没有展示课程也留空。与两列展示课程无关的历史来源不会参与判断，不按来源名或文件名猜测业务关联。复用现有 resolvedTermKey 的正式旧格式解析，不另建配置系统。

JVM 覆盖单一来源、多个来源共用学期、有效＋未配置／缺失／无效配置的相关来源、冲突学期、配置映射身份不符、无关历史来源、本地无关联课程、周日跨周及不匹配时区。原来只有来源元数据而没有任何近期课程的测试已改为真实近期实例，避免用无参与者状态证明教学周可靠。

## 午夜快照

近日 Snapshot 保存不可变的 CollectionBasis（投影日期、ZoneId）和当次计算的教学周标签。课程行、日期标题、标题点击及课程点击使用该基准。渲染不会重新计算一个新日期后拼接旧课程。

instanceSnapshot 在显示前校验当前日期／时区；跨日或时区变化时返回空行及刷新提示，不携带旧教学周。失败快照仍显示错误，无旧课程。新投影完成后完整切换到新基准。适配器及日期导航身份包含基准，防止旧标题下的适配器读到下一天的数据；同一天普通刷新不改变此身份。

集合 Factory 保存父 RemoteViews 传入的预期基准。getCount/getViewAt 校验基准及有效期，失效后不返回旧行；每个失效 Factory 最多向现有协调器请求一次刷新，不新增 Store 读取渠道、计时轮询或精确闹钟。已删除组件不会由有效性检查再发起刷新。

JVM 用固定 10/29 23:59:59 与 10/30 00:00:01、时区变化验证基准有效性。Android 测试直接发布受控的跨午夜课程快照，在测试容器应用 RemoteViews：旧基准标题为 10.29；跨日显示 10.30 时两列必须隐藏；新快照的两列日期为 10.30／10.31，跨午夜课程仍保留；失败后无旧行。两端各通过 1 项，不修改系统时间，也不声称自然午夜的 Launcher／Doze 实测。

# X08E 首次横划：部分优化，性能验收未完全达标

基线为原 Draft PR64 `edce41c`。**正确性测试通过，但不能据此宣布本任务的性能完成条件全部通过。** 本次降低了首次 MOVE 的集中同步工作；25%→80% 快速跳动仍可出现补建停顿，原生连续拖动仍有长帧，距离正常触摸帧预算尚有差距。

## 修改与边界

- 新增像素无关的只读展示快照，复用原 ScheduleProjection、节次验证和重叠/并排算法。纯投影、文字与几何由单个按需后台工作线程准备；后台不创建、测量或访问 View 树。
- 仅在**可见完整课表且开启横划**时预备当前周相邻两周的数据。最多保留当前 ±1 周三份数据，不缓存相邻整页 View。队列清理取消任务，空闲线程 1 秒退出；关闭页面/窗口或开关时清理。源数据/刷新、布局/配色/排版、主题、语言、时区、密度/字号/显示配置均有失效边界；尺寸变化还由手势视口取消与重新测量保护。
- Epoch 拥有各自的数据容器；旧计算即使延迟返回也不能发布到新容器。发布和周范围收缩由短临界区保护，计算不在锁内进行。展示缓存不是课程写入状态，未修改存储、编辑、导入或同步。
- 预览仅先创建容器，再同步构建真正进入裁剪区域的日期列/按钮/课程。不可见列在首次绘制后按有限帧任务补齐；即将进入可见区的内容必须先准确构建和测量，**没有限制拖动比例、假课程或可见的空白占位替代**。回弹/离页/刷新等取消任务；成功仍转正同一棵视图。
- 网格规则线改为在列背景之上、卡片之下直接绘制，保留坐标、厚度和颜色，避免为七列每个刻度分配独立 View。卡片字体、配色、今天高亮、Phone 视觉/节次轴及 Home/Apps 按钮未改。
- 调查了省去 TextView 默认样式的方案，但多行换行像素对比失败，**没有采用**该方案。未用整页 Bitmap、持续离屏渲染或新依赖掩盖问题。

## 测量方法

同一物理 X08E（API 28、1280×800），相同每周 21 门、相邻周日期标题不同的隔离夹具，三种布局均开启课程配色及信息排版。仅安装 `.testbed`，未升级日用 App，未操作原厂服务。

基线是在 `edce41c` 功能路径上只增加计时探针与相同采样测试。[before.json](before.json) 和 [after.json](after.json) 每种布局各 6 个样本：第 0/3 次新建页面，其他次在同一 Activity 中刷新并重复。这里的冷/重复表示**页面/预览冷准备与上下文重复使用**，不是每次重新启动 OS；“repeat”样本也刷新了展示 epoch，不能冒充保留数据缓存的纯热命中。每次首个 MOVE 直接达到 25%，随后跳到 80%，最后松手。记录调用壁钟时间、目标页首次 OnDraw、提交回调及 FrameMetrics，未只测最终动画。

[native.json](native.json) 另含每种布局 3 次系统触摸注入：首次向前、反向、再次向前，覆盖保留快照的反向/重复路径。使用连续小步触摸，不与 25% 跳步样本混为同一指标。

`X08ePreviewTrace` 和可选 `previewTiming` 只在 instrumentation 接入时收集；应用默认没有采样器、样本队列或轮询。阶段有嵌套，**不可直接相加**。OnDraw 是真实目标页进入 Android 绘制的时刻，并非面板光子/触摸到扫描输出的硬件测量；FrameMetrics 则另记录该手势窗口内的帧耗时及丢弃回调计数。不能把后台计算完成或 OnDraw 等同为稳定呈现。

## 仍未解决的性能部分

- 25%→80% 快速跳步的补建，时间布局最高 **82.7ms**、节次最高 **71.1ms**；经典最高 **25.9ms**。工作分布改变后，这条路径仍明显超预算，不能称“后续 MOVE 全部流畅”。
- 原生手势中的隐藏列单次任务最高约 **23ms**，手势/收尾窗口 FrameMetrics 最长帧仍为 **72–90ms**；每段样本有 **12–23 帧超过 32ms**。没有把它们过滤掉或把阶段搬走当作消失。
- 松手触摸调用本身约 **0.8–16.4ms**，提交回调没有出现原先整周重建，但仍有数十 ms 工作；原生样本提交约 **35–53ms**。未达到所有关键阶段接近 16ms 的要求。
- 快照未就绪时仍有同步单周纯计算回退；缺失缓存、极快大幅位移、复杂/更多课程及关闭动画时极短 fling 的最坏性能，不能用已预备快照样本兜底宣称通过。延迟计算的取消和失效正确性已测，但不是这些路径的性能通过证据。
- 未做物理面板扫描延迟、长期 CPU、峰值内存基准或 soak。结构上限制三份数据、一个计算线程、当前页加一个预览；没有据此伪造实测内存数字。

因此结论为：**集中首阻塞显著降低，正确性通过，性能目标部分完成；整体性能验收仍未通过。** 后续需要继续减少原生控件建/测开销，而不能放宽该结论。

# 最后一轮低复杂度试验：撤回，保留性能边界

> 本页为历史试验结论。用户随后确认真实 X08E 使用流畅度足够，要求停止优化并转 Ready；最新决定见[实机使用验收](../acceptance.md)。

基于 `156752c`，本轮尝试移除冷缓存 MOVE 中的同步展示计算。**没有找到同时改善主线程和真实内容响应的低风险方案，试验已全部撤回；应用代码保持 `156752c`，PR 继续 Draft。** 不以事件返回更快作为性能通过，不继续叠加异步状态或扩展经典渲染重构。

## 尝试及撤回原因

复用原三周只读缓存，未命中时不再同步回退；只在有效横划内最多重试八帧。准备期间旧页提供 touch-slop 范围方向反馈，真实数据就绪后挂载真实邻周，并尝试有限追随过渡；提前松手回弹，取消/失焦/刷新移除重试。没有后台创建 View，没有假课程或位图页面，也没有第二套展示缓存。

同一物理 X08E/API28/1280×800、每周21门课程、原工具每模式6样本，强制清空缓存后立即移动到25%，再快速移动到80%。下表为中位/最大 ms；基线取上一轮同场景原始样本，未控制温度/DVFS，不能视为严格统计试验。

| --- | --- | --- | --- | --- | --- |

实验说明首次 MOVE 内确实不再计算投影，但创建/测量可见真实内容仍集中在后续主线程阶段；有的真实绘制反而更晚，经典后续 MOVE 达到162ms。**这正是把阻塞转移到发布/补建阶段，不能接受为完成。** 只保存数据和[被拒补丁](rejected.patch.gz)供复查，不将该实现交付到应用。

原始数据为 `rejected-{cold,jump,release,native}.json`；对应 `.txt` 是采样方法运行记录。数字汇总见 [summary.txt](summary.txt)。OnDraw 是 Android 绘制入口，不是屏幕扫描/光子延迟。采样方法运行成功只代表采集及日期断言成立，不代表性能合格。

## 保留的合理边界与未完成项

- 保留上一轮已验证的真实双页、Epoch快照、轻量网格卡片、原位转正及清理；未改Phone视觉、按钮、存储/同步或版本。
- 冷缓存同步回退、经典自然高度建/测、快速完成尤其零动画补建仍是未解决项。经典兼容路径的换行、独立滚动和操作规则继续保留；本轮没有稳定新证据支持强制改成自绘经典卡片。
- 上一轮已有零动画最大UP约153/88/69ms与经典P95约144ms仍适用，本轮没有把这些数字抹掉，也没有宣布恢复后的版本更快。
- 在不预建整页、不允许假内容且不扩大渲染重写的限制下，本轮停止增加复杂度。后续可行选择是独立评估经典文字/测量成本或收窄冷准备交互契约；这些均未实施、未验证，不算完成项。

## 验证事实

- 本轮构建与受影响快照/几何JVM检查执行成功；撤回后[重新构建](restored-build.txt)，并把隔离testbed恢复为保留实现。没有升级日用客户端，没有更改原厂服务或数据。
- 候选冷/预热/快拖/释放/原生采样均运行，日志及全部原始帧已保存，**不是性能PASS**。
- [早期原型定向检查](experimental-correctness.txt)3/3；[候选共享组件Phone检查](experimental-phone.txt)2/2。它们只验证该阶段的部分正确性，不是最终流畅度验收；被拒补丁中的新增“提前松手”专测未单独执行，不声称通过。
- 恢复保留代码后，快速释放/fling完整性和延迟快照失效再做[实机回归](restored-smoke.txt)。没有重复协议、fnOS或长时soak，也未测长期CPU/峰值内存及物理面板时延。

最终结论：**本轮没有可保留的净性能收益，功能代码已撤回；整体性能目标仍未完成，保持Draft，不合并、不发布。**

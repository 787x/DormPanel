# PR73：Factory 初始化去重与无课教学周

基线 fa6788b，仅更新原 PR73。

## 重复物理读取

原因是 Factory.onCreate 与失效检查都走 request；request 是真实数据变化语义，每次增加 generation，第二列初始化会让在途第一次结果过期，继而再读取。

新增轻量 ensure 路径：在主线程查询同一份快照的有效性。快照有效则不读；缺失／失效时加入 active 或 dirty 的既有读取，不增加 generation；没有读取才经原 request 启动一次。真实更新信号、时间广播、恢复 alarm 仍使用 request，因此在途新提交仍能撤销旧结果并读取最新数据。删除 ID 的 Factory 不进入 ensure。

没有新的 Store、线程、固定延时、轮询或数据通道；原有超时、旧结果阻止、两个物理名额上限保持不变。两个独立 ListView 及通知、身份、点击规则不变。

## 无课教学周的证据层次

1. 有显示课程：仍严格核验今天 remaining＋明天 all 的相关来源。
2. 无显示课程但今天有已结束课程：使用今天 all＋明天 all 确定来源。
3. 两天完全无课：不从 profiles 选默认值。使用现存、来源绑定的导入实例，按每个来源的实际最早 start／最晚 end，确认课程记录日期跨度与当前两日窗口相交；只将这些有当前日期证据的来源纳入判断。历史记录全部结束的来源不参与。相关来源仍逐一要求相同有效学期、正确配置身份、设备时区、两日阶段及正周数。

TermScheduleProfile 没有学期结束日期，所以不能仅凭它的 phaseOn 非空认定当前学期。没有实际记录范围证据（例如只有内置 profile、只有来源元数据、全部是历史课程）时保守留空。未关联学期的本地课程／本地共享安排存在时，空课回退也保守留空，不借用别的导入源来猜。本轮不新增或推断学期结束日期，不按来源名称或 termKey 的年份猜当前学期。共享安排独有而导入实例范围不足等场景仍可能留空，这是保守的证据边界。

教学周仍在 publish 中用 Snapshot 的日期和时区一次计算。跨日／时区失效时旧周次清空；新快照的日期、课程与周次共同更新。

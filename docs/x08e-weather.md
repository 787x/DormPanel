# X08E 天气服务

## 天气中心

轻触任意桌面天气卡片进入天气中心，页面会打开卡片绑定的地点和来源。长按继续打开快捷详情，其中的「查看天气」也能进入天气中心。旧版默认天气卡片打开 HA 默认天气或演示天气。首页下滑后，可从控制中心直接进入「天气中心」。

左侧选择地点，右侧滑动查看详情。点击地点名称旁的来源按钮可以在和风和已关联的 HA 实体之间切换，按钮列表也会显示已有的状态和更新记录。天气中心的查看选择独立于桌面卡片。在「地点管理」可编辑名称、时区、坐标或来源，也可删除地点、置顶收藏及调整同组顺序。已保存地点保留原 ID。删除地点或移除来源后，对应卡片可在长按详情中重新绑定。

添加地点时可以手填经纬度，也可从「在地图上选点」打开内置离线地图。拖动、双指缩放或使用缩放按钮，点击地图或选择地图中心，再将坐标回填到地点表单。填写名称和 IANA 时区后保存。地点表单保留输入的经纬度精度，实际天气空间分辨率由服务提供者决定。底图使用 Natural Earth 公共领域的 1:50m 陆地轮廓（4.1.0）和居民点（5.1.2），适合概览选点，支持离线使用。底图加载失败时仍可手填坐标。[Natural Earth 使用条款](https://www.naturalearthdata.com/about/terms-of-use/)

- 「天气预报」默认展示未来 24 小时，可切换更长范围并横向滑动。触摸图上的时刻或下方天气条目查看明细。折线按实际时刻绘制，数据缺测会形成断点。重复的本地时刻附带 UTC 偏移。
- 多日预报最多展示 10 天，所有日期共用一个温标。触摸单日可展开有数据的白天、夜间、气象指标和天文信息。HA 根据实体提供的实际类型展示小时、每日或昼夜预报。
- 「分钟降雨」「空气质量」「生活指数」「日月天文」在打开各分区时加载。AQI 趋势按标准分开。天文优先复用今日预报中的日出日落、月升月落及月相，缺少所需字段时再查询专项接口。打开「历史天气」后选择最近十天中的日期，需要该来源具有和风 Location ID。[和风指数类型](https://dev.qweather.com/docs/api/indices/indices-type/) · [和风每日天气预报](https://dev.qweather.com/docs/api/weather/weather-daily-forecast/)
- 有效预警显示在实时天气上方，触摸查看生效时间、发布单位、正文、防御建议及归因。各分区独立显示数据状态、更新时间和来源。「刷新可见天气」沿用和风缓存、最短间隔和预算，反馈刷新开始、排队、请求合并或限制原因。

## 配置和检查

从首页下滑进入控制中心，选择「天气服务与地点」。打开「和风服务配置」，输入和风控制台分配的专属 API Host。JWT 模式填写凭据 ID、开发者 ID、项目 ID 和 Ed25519 PKCS#8 私钥。已有 API Key 的用户可以切换认证方式。保存后可测试已保存的凭据。测试使用已配置的第一个和风地点，或使用北京的公开示例坐标发出一次实时天气请求。该请求计入本机预算。

通过「添加地点」设置名称、经纬度和 IANA 时区，例如 `Asia/Shanghai`。已连接的 Home Assistant 天气实体会出现在同一表单中，可以为地点同时启用和风和多个 HA 来源。地点列表支持编辑、删除、切换检查来源及清除缓存。历史天气只接受明确的和风 Location ID。输入经纬度时会保留原始精度。

城市或区县搜索显示行政区划、同名候选和数据归因。选中后可「临时预览」或「收藏此地点」。预览使用当前 GeoAPI 返回的地点和时区，仅在当前应用进程内有效。预览列表用「临时预览」标记，且提供「收藏此地点」入口。

收藏时填写自己的名称和时区。应用查询和风独立发布的公开中国城市目录，核对该地点编号确实在公开目录中，再保存编号、自己的名称和时区。重启后按编号精确解析经纬度。解析结果仅在进程内复用，天气快照可以离线回读。目录不发送和风认证信息，搜索结果和目录内容均无磁盘写入。已收藏地点编辑后保留原 ID。

官方缓存指南对 GeoAPI 地理字段的逐字段保存权限没有明确授权。公开目录未收录的地点可使用「用自有坐标收藏」，自行填写独立获得的名称、坐标和时区。扩大可直接持久化的 GeoAPI 范围需要和风明确许可。[和风公开地点编号目录](https://dev.qweather.com/docs/resource/location-list/) · [地点目录用途](https://github.com/qwd/LocationList) · [GeoAPI 缓存指南](https://dev.qweather.com/docs/best-practices/cache/)

检查界面打开后订阅实时天气和小时、每日预报。和风提供「刷新核心天气」与「刷新选中数据」。后者只刷新所选数据块，并支持专项日期。HA 提供「查看选中数据」，由 HA 状态和预报订阅返回服务器已有数据。关闭检查界面即释放该界面的订阅。归因和许可随各数据块展示，天气预警与 AQI 的来源声明完整显示。[和风注明来源](https://dev.qweather.com/docs/terms/attribution/)

## 接口和单位

| 数据 | 和风接口 | 请求参数 |
| --- | --- | --- |
| 地点 | `/geo/v2/city/lookup` | `location`、`number`、`lang` |
| 实时 | `/weather/v1/current/{lat}/{lon}` | `lang` |
| 小时 | `/weather/v1/hourly/{lat}/{lon}` | `hours` 1–240、`lang` |
| 每日 | `/weather/v1/daily/{lat}/{lon}` | `days` 1–10、`lang` |
| 预警 | `/weatheralert/v1/current/{lat}/{lon}` | `lang` |
| 空气质量 | `/airquality/v1/{current,hourly,daily}/{lat}/{lon}` | `lang` |
| 分钟降水 | `/v7/minutely/5m` | `location`、`lang` |
| 生活指数 | `/v7/indices/{1d,3d}` | `location`、逗号分隔的 `type`、`lang` |
| 天文 | `/v7/astronomy/{sun,moon}` | `location`、`date`，月相另有 `lang` |
| 历史天气 | `/v7/historical/weather` | Location ID、`date`、`unit=m`、`lang` |

天气参数以十进制点格式化，坐标在请求时四舍五入至两位小数。v1 路径使用纬度、经度顺序，v7 位置参数使用逗号分隔的经度、纬度。坐标、日期及 API 参数影响共享缓存键，名称仅用于展示。天文支持当地今天起 60 天，历史支持当地昨天起 10 天。分钟降水在支持区域提供约两小时的五分钟累计量。[和风 API 文档](https://dev.qweather.com/docs/api/)

天气量统一为 °C、m/s、hPa、m、mm、mm/h，百分比为 0–100。空气污染物浓度保留上游单位和 AQI 标准。缺失和不合法数值为空。天气代码保留原值。带偏移量的时间转换为 `Instant`，日历日期按地点时区计算。历史接口给出的无偏移时间作为当地日期和钟表时间保存，以保留夏令时歧义。[和风单位](https://dev.qweather.com/docs/resource/unit/)

## 安全和持久化

和风连接仅接受专属 `qweatherapi.com` 主机名或对应的 HTTPS 地址。OkHttp 验证 TLS，关闭重定向和连接失败自动重试。API Key 使用 `X-QW-Api-Key` 请求头。JWT 使用 Ed25519，签发时回拨 30 秒，总有效期 15 分钟，提前 60 秒换发。签名使用独立 Java EdDSA 实现，在 Android 9 上可运行。凭据与其绑定的主机和配置 ID 一起通过 Android Keystore AES-GCM 加密保存，凭据文件排除在 Android 备份和设备迁移之外。解密失败会显示重新配置提示。错误提示使用本地分类及状态码，省略凭据和服务端原始错误正文。[官方认证](https://dev.qweather.com/docs/configuration/authentication/) · [API Host](https://dev.qweather.com/docs/configuration/api-host/)

用户地点、来源关系与刷新策略使用独立设置文件。天气快照使用应用私有目录中的原子文件，支持重启回读，磁盘最多保留 128 份，每份最多约 2 MiB。磁盘写入和回读确认都在后台执行。界面区分正在写入、已保存、写入失败和仅本次会话可用。写入失败时仍显示内存中的天气，后续成功获取的数据可再次保存。和风配置换代与 HA 端点、认证身份共同隔离缓存，已撤销请求的回调会被拒绝。已有布局、卡片与 Room 数据结构沿用原路径。

「清除离线缓存」删除磁盘记录，当前会话仍可查看内存中的天气及其原始获取时间。按地点清理会保留其他地点共用的数据组；「清除全部离线缓存」可以一并清理这些组。清理前在途的 HTTP 响应可以继续用于当前会话，后续请求或 HA 新推送才能重新保存。清理结果会提示清除成功、保留共用缓存或磁盘删除失败。最短请求间隔、限流和预算仍然生效。

## 刷新和预算

在「和风服务配置 → 刷新周期设置」选择「节省请求」「标准」「及时更新」或「自定义」。单位为分钟。

| 数据块 | 节省请求 | 标准 | 及时更新 | 自定义范围 |
| --- | ---: | ---: | ---: | ---: |
| 实时天气 | 30 | 15 | 10 | 10–180 |
| 小时预报 | 90 | 45 | 30 | 30–360 |
| 每日预报 | 360 | 120 | 60 | 60–720 |
| 预警 | 20 | 10 | 5 | 5–20 |
| 实时 AQI | 90 | 45 | 30 | 30–360 |
| 小时 AQI | 120 | 60 | 60 | 60–720 |
| 每日 AQI | 720 | 480 | 480 | 480–1440 |
| 分钟降水 | 10 | 5 | 5 | 5–30 |
| 生活指数 | 720 | 360 | 360 | 360–1440 |

周期保存后立即重新计算缓存的新鲜度和下次请求。每日预报、每日 AQI、生活指数也会在地点当地午夜变为待更新，下次请求仍受该类型的最小间隔约束。预警单条有效期可以早于缓存有效期，取消、被取代、过期的预警不计入当前有效。天文和历史按日期缓存，历史只按需加载。

手动刷新可以在普通新鲜期结束前执行，最早间隔为表中的自定义下限。同键在途请求共享。达到冷却、429、认证、权限或月预算限制时显示原因，有明确期限时显示最早可请求时间。刷新期间继续显示上一次数据，成功响应可区分内容变化、内容未变和服务无数据。失败保留最后一次数据与更新时间。

自动刷新仅对有需求的数据块调度，HTTP 并发最多两个，核心天气优先。后台或面板黑屏会停止新系统的订阅和刷新任务，恢复前台后按需刷新。确认默认网络恢复后，仍在自动订阅且已过期的核心天气可提前重试，单键相邻提前重试至少相隔一分钟。服务端 429、认证、权限和月预算限制继续生效。[和风缓存建议](https://dev.qweather.com/docs/best-practices/cache/) · [请求优化](https://dev.qweather.com/docs/best-practices/optimize-requests/)

和风 HTTP 400、响应体中的等价参数错误及其他确定性的请求拒绝会停止相同参数的自动和手动重试。更换实际请求参数或服务配置后可以重新请求。现有天气和其他数据块继续可用。429 仍按服务端重试时间和退避处理，5xx 和临时故障仍使用原重试策略。[和风错误码](https://dev.qweather.com/docs/resource/error-code/)

检查界面独立显示和风网络状态。系统确认默认网络具有互联网连接时显示已连接；有网络但尚未验证时显示未确认；无默认网络时显示离线并暂缓和风天气刷新。离线时数据仍按原有效期从新鲜变为过期，无缓存时提示无法获取。联网时仍新鲜的数据继续按原计划刷新。HA 连接及天气可用性沿用 HA 自己的 WebSocket 和实体状态。

本机预算按 UTC 月份计数，默认 30,000 次。按标准模式全天订阅，单个地点每月约 4,200 次核心天气请求，可覆盖约六个这样的地点并留有余量。和风天气和基础服务当前以账号同计价分组的累计请求量进入阶梯，首 50,000 次处于零价阶梯。本机上限和估算仅覆盖当前设备，账号实际费用取决于全部调用端和服务。[和风按量计费定价](https://dev.qweather.com/docs/finance/pricing/)

设置页显示已使用、上限及余量。周期配置页分别估算已保存地点的核心天气用量，以及当前活跃自动订阅的用量。相同键只计一次，按整月全天运行，计及可能的跨日更新，未计入手动刷新、重试和地点解析。预算达到 80% 时预留剩余额度给核心天气，达到上限暂停和风请求，于下个 UTC 月或提高预算后恢复。修改上限保留当月计数。测试连接、GeoAPI 搜索和编号解析都计入本机预算。

HA 当前天气从现有实体存储读取，并跟随原连接的状态事件。同一实体和预报类型共享 `weather/subscribe_forecast`，订阅失败或无初始事件时回退 `weather.get_forecasts`。原版天气卡片保留 Preferred weather 及原全局投影，与新消费者共享同类型的 HA 预报订阅。和风配置及数据与 HA/Demo 后端模式独立。[HA 天气实体](https://developers.home-assistant.io/docs/core/entity/weather/) · [HA 预报订阅实现](https://github.com/home-assistant/core/blob/dev/homeassistant/components/weather/websocket_api.py)

## 桌面天气卡片

进入桌面编辑后，选择「添加卡片 → 天气」，从已保存的地点和来源中选择并确认。同一地点可以使用多个来源，同一来源也可以添加到多张卡片。地点尚未保存时，可通过选择器中的「天气服务与地点」收藏地点或关联 HA 天气实体。选择「默认天气」会继续显示 HA Preferred weather 或 Demo。

短按天气卡片打开天气中心。长按面板提供「切换天气」「刷新天气」和进入天气中心的「查看天气」。切换只更新当前卡片的配置，保留位置和尺寸。选择器等待 Room 回执。保存失败时保留修改并提供「重试保存」。同一地点换来源沿用卡片别名，换地点时默认使用新地点名称。长按详情中的「卡片显示设置」可设置或清除别名，并选择自动、体感温度、湿度或风速。移除地点或来源后，卡片提示绑定已失效，可从详情重新选择。显式卡片继续使用其绑定的来源，即使 HA Preferred weather 已更改。

卡片配置存放于原 Dashboard Room 的 `configurationJson`，沿用 `weather` 类型和卡片 ID。空对象表示默认天气。版本 1 保存 `version`、`placeId`、`source`，以及可选的 `displayName`、`metric`。来源引用沿用地点存储中的 `qw`、`qw-city` 和 `ha` 表示，写入时验证来源归属及地点是否已保存。

显式卡片按尺寸订阅实时天气及一种预报。和风卡片使用每日预报并在卡片上提供官网链接。HA 卡片根据实体声明和预报状态优先使用每日预报，其次使用昼夜或逐小时预报。HA 预报按地点当地日期或预报时段筛选当前及未来条目。每日预报在当地午夜结束。小时预报缺少显式结束时间时按一小时计算，昼夜预报按当地时钟推算 12 小时，若下一昼夜时段更早开始，则采用该交接时间。空响应保留仍有效的旧条目并标记为空响应，最后一个可用时段结束时切换至可用的次级预报。卡片共用 Repository 的探测计划，常规探测间隔至少 15 分钟，单次最多 90 秒，恢复数据后自动切回。明确不支持的类型在能力变化或连接恢复后重新评估。详情额外订阅逐小时预报，HA 详情还接收可用的昼夜预报，和风详情还接收空气质量与预警。详情关闭时释放这些需求。和风详情提供官网链接，分别完整展示实时天气、预报、AQI 和预警响应中的归因，并将其中的网页地址显示为可点击链接。[和风天气注明来源](https://dev.qweather.com/docs/terms/attribution/)同一查询的卡片与详情共用刷新和缓存。日期和时间按所绑定地点的时区显示，默认天气以设备时区显示。天气图标和中文状态使用上游状态码，并为未知代码保留通用图标。[和风天气图标代码](https://icons.qweather.com/en/icons/) · [HA 天气状态](https://developers.home-assistant.io/docs/core/entity/weather/)

## Repository 接入

从 `DashboardBackend.weatherRepository` 获取同一个 Repository。通过 `places.places`、`places.get(id)`、`places.observe` 读取地点配置。卡片可保存地点 ID 与明确的 `WeatherSourceRef`，以便不同卡片独立选择来源。切换绑定时关闭旧订阅，并用新地点和来源调用 `observe`。地点或绑定移除会通知当前观察者。

向 `observe(placeId, source, WeatherQuery(...), automatic, listener)` 传入所需数据块。默认只自动刷新核心块。长按详情或天气中心可以在可见时订阅专项数据，或对和风订阅调用 `refresh()`。返回值区分开始、合并、排队和限制原因，有明确限期时带最早请求时间。最终结果由快照监听器给出。快照的 `persistence` 字段独立标记离线保存状态，`network` 字段提供独立于数据新鲜度的和风网络状态。HA 页面直接订阅服务器已有数据。使用 `capabilities` 读默认请求范围的已知状态，使用各 `WeatherSnapshot` 显示请求特定范围的状态、数据、来源、上游时间、获取时间及过期时间。预警模型将当前有效、即将生效和撤销消息分别暴露。消费者应在界面移除、卡片换绑或详情关闭时调用 `close()`。这些 API 在主线程调用，网络与磁盘工作由内部执行器负责。

点击动作通过 `WeatherCardNavigation` 向 Dashboard 页面传递卡片 ID、地点 ID 和 `WeatherSourceRef`。默认天气没有显式地点及来源参数。`QUICK_DETAIL` 打开快捷详情，`WEATHER_CENTER` 通过页面工厂打开 `PanelPage.WEATHER`。天气中心按当前地点和分区管理订阅，并在页面退出、进入后台或黑屏时释放需求。

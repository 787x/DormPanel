# Phone P1：HyperOS 人工实机验收手册（PR77）

本文档用于 **Android 手机/平板 + HyperOS（含 MIUI 14 低版本对照）** 上人工验收
[PR77 P1 主动课程跟踪](https://github.com/787x/DormPanel/pull/77) 的行为。
所有步骤使用 **隔离测试包**，不写入日用数据库、不触碰正式签名与版本号。

---

## 1. 所需材料

| 材料 | 说明 | 获取方式 |
| --- | --- | --- |
| **测试版 APK** | `phone-app-x08eTest.apk`（包名 `com.dormpanel.timetable.testbed`，版本 `0.1.10`，debug 签名） | `./gradlew :phone-app:assembleX08eTest` 产物：`phone-app/build/outputs/apk/x08eTest/phone-app-x08eTest.apk` |

## 2. 安装与准备

```bash
# 安装测试包
adb install -r phone-app/build/outputs/apk/x08eTest/phone-app-x08eTest.apk

# 授予通知权限（Android 13+，也可在系统设置里手动开启）
adb shell pm grant com.dormpanel.timetable.testbed android.permission.POST_NOTIFICATIONS

# 确认能读取 logcat 标记
adb logcat -d -v time | grep -i DormPanelCourseNotice
```

在测试包内：
1. 导入测试课表（建议：今天 10:00–10:45、11:00–11:45 两节；另加一节 13:30–15:00 用于观察重叠/跨时）。
2. 「管理 → 课程通知」设为 **“仅课前和上课中”**，提前 15 分钟，锁屏隐藏开启。

## 3. 验收内容、方法与预期结果

> 每个用例请记录：机型 / HyperOS & Android API / 操作时间 / 实际观察 / 截图或录屏 / 结果 PASS/FAIL/未验证。
> **不要把“代码审查通过”“JVM 测试通过”“notify() 返回正常”当作实机 PASS。**

### 3.1 普通课程通知（P0 回归）
| 步骤 | 方法 | 预期结果 |
| --- | --- | --- |
| 课前窗口 | 在开课前约 15 分钟保持通知开启、锁屏 | 出现「即将上课 · 课程名」，含 Chronometer 倒计时到开始；标题被脱敏的 publicVersion 不含教室 |
| 上课中 | 开课后 | 变为「正在上课 · 课程名」，倒计时到下课 |
| 下课 | 下课后 | 撤下或切换为下一节；不残留过期状态 |
| OFF | 设为「关闭（默认）」 | 现有通知立即取消；下次不出现 |
| 权限关闭 | 系统设置关闭应用通知 / 渠道关闭 | 不显示通知、不崩溃、不循环弹权限；重新开启后恢复，**配置不被重置为 OFF** |

### 3.2 主动跟踪（P1 核心）
| 步骤 | 方法 | 预期结果 |
| --- | --- | --- |
| 仅能跟踪进行中课程 | 未上课时点「跟踪当前课程（实验）」 | 提示「当前没有正在进行的课程」，不进入跟踪 |
| 正常开启 | 上课中点「开始跟踪」 | 通知显示「正在上课 · 课程名」+「结束跟踪」按钮；「课程通知」对话框显示“正在跟踪 + 预计结束时间” |
| 内容修改跟随 | 跟踪中在课表编辑该课标题/教室（不改时间） | 通知标题/内容更新为新内容，会话不中断 |
| 时间/取消变化 | 跟踪中把该课改到别的时间或删除 | 会话失效并结束；对话框回到“未在跟踪”；通知恢复普通或撤下 |
| 自动结束 | 等到本节课结束 | 自动结束跟踪，通知按用户原普通模式恢复（不自动开启新跟踪） |
| 应用内结束 | 跟踪中点「结束跟踪」 | 立即结束；通知恢复普通或撤下；无残留提升请求 |
| 通知操作结束 | 在跟踪通知点「结束跟踪」按钮 | 同应用内结束 |
| 通知删除 | 手动滑掉跟踪通知（若系统允许） | 会话结束（deleteIntent 回调），不再显示提升 |
| OFF 时开启 | 在普通通知 OFF 状态点「开始跟踪」 | 提示先开启普通通知；**不暗中修改设置** |
| 关闭通知同时结束 | 跟踪中把普通通知设为 OFF 并保存 | 跟踪会话结束，通知取消 |
| 进程重建 | 跟踪中强行停止应用再启动 | 若课程未结束且设置仍开启，恢复跟踪；否则按规则失效，不残留 |

### 3.3 Android 16+（API 36，HyperOS 3 若为 Android 16 设备）
| 步骤 | 方法 | 预期结果 |
| --- | --- | --- |
| 系统支持/资格 | 诊断面板（课程通知 → 查看通知能力诊断） | “Live Updates 系统支持：支持（API 36+）”；“提升资格”显示 `true`/`false`（系统是否允许本应用申请） |
| 有效跟踪时请求 | 跟踪中查看 logcat `dumpsys notification` / 通知对象 | `setRequestPromotedOngoing(true)` 被调用（诊断记录“最近一次提升请求”时间点）；`Notification.flags` 含 `FLAG_PROMOTED_ONGOING` 则表示系统确实标记为 promoted |
| 实际提升展示 | 锁屏/状态栏观察 | **可能**出现 chip 或锁屏置顶；**不保证** — 若系统不支持/不允许/用户关闭，则以普通通知显示（这是可接受结果） |
| 结束跟踪后 | 结束后查看新的普通通知 | 不再携带提升请求（无 `FLAG_PROMOTED_ONGOING`，诊断不再新增提升请求时间点） |
| 权限入口 | 诊断面板「实时更新权限」 | 跳转到 Android 实时更新（promoted notifications）设置页 |

### 3.4 API 28–35（HyperOS 2 / MIUI 14 低版本对照）
| 步骤 | 方法 | 预期结果 |
| --- | --- | --- |
| 诊断 | 查看诊断 | “Live Updates 系统支持：不支持（API 35 及以下）”；不会调用不支持 API |
| 跟踪 | 上课中开启跟踪 | 普通通知 + 「结束跟踪」按钮；**不**请求提升；其余 3.2 行为一致 |

### 3.5 诊断面板真实性
| 步骤 | 方法 | 预期结果 |
| --- | --- | --- |
| 计划唤醒 | 开启通知后查看诊断 | “下一次计划唤醒”有真实时间；关闭通知后该行显示“无记录”（已清除） |
| 广播/notify | 触发一次课前/开课 | “最近闹钟广播收到”与“最近 notify() 正常返回”更新 |
| 失败 | 断网/Store 故障时观察 | “最近错误”出现对应阶段；诊断不把失败误报为成功 |
| 小米焦点 | 诊断 | 焦点协议版本与用户开关为只读尽力查询；不解释为已获超级岛授权 |

## 5. 已知边界与不允许的声明

- 课程进度不是 Android 官方典型 Live Updates 用例；P1 标记为实验性，**不保证系统认定适合提升**。
- `setRequestPromotedOngoing(true)` 调用成功 ≠ 实际获得提升；诊断只记录“请求”，实际提升需系统对象/UI 人工确认。
- HyperOS 后台可能延迟或阻止本地通知；**强行停止应用后不承诺持续工作**。
- 小米后台本地通知白名单没有可靠公共查询 API；若后台不出现，按文档第 6 步区分原因，不要写成“厂商阻止”。
- 小米超级岛/焦点通知（P2）不在本 PR 范围：不写入 `miui.focus.param`，不宣称已获超级岛授权。
- 本轮验收**不要求**：后台数小时驻留、长期 Doze 压力测试、Android 16 实机（具备时建议做 3.3）。

## 6. 后台不出现通知时的排查顺序

1. 诊断面板：确认“下一次计划唤醒”已设置（未设置 → 调度未提交）。
2. logcat `DormPanelCourseNotice`：确认闹钟广播是否收到（未收到 → Doze/OEM 延迟）。
3. 确认 Store 读取是否失败（诊断“最近错误”）。
4. 确认 `notify()` 是否被调用（诊断“最近 notify() 返回”）。
5. 若 1–4 均正常但仍不可见 → ROM 过滤/后台白名单，需系统侧人工确认，不归因于应用。

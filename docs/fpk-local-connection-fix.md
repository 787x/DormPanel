# FPK 0.4.1 本地连接按钮修复记录

日期：2026-10-22（Asia/Shanghai）。基线：`bb62cf6`，即已发布 `fpk-v0.4.1` 对应的 main。

## 实际故障与复现

先在独立实例中延迟 `/api/manage`，用 Edge、1280×800 视口运行真实 `index.html` 和 `app.js`，确认原代码点击“新增本地目录连接”后弹窗始终未打开，产生 `Cannot read properties of undefined (reading 'roots')`。堆栈为 `connectionDialog → dialog → build`，发生在 `showModal()` 之前。相同测试修复前失败、修复后通过。

随后按用户指认检查 `https://qweasdf.fnos.net/` 的已登录真实页面，确认：

- 页面显示 0.4.1，工作区选择器和管理列表为空。
- 点击本地按钮无可见反馈，控制台记录同一异常，原页面行号为 `app.js:830 → :271 → :821 → :871`。
- 隐藏的首页 `#status` 内容是“页面来源不匹配”。因此管理数据未初始化是更早的初始化失败所致，并非只是一段短暂加载延迟。
- 相比之下，测试机 `192.168.3.153:5666` 的原版 0.4.1 正常加载后能打开弹窗，并列出私有目录和 fnOS 应用共享目录；取消未保存。

原后端检查完整合法页面 Origin 后，还要求该域名与网关交给后端的 Host 域名相同。真实页面的 `location.origin` 是规范 HTTPS Origin，故结合该检查条件，可推断公网代理交给后端的 Host 与公网域名不同；本次未读取公网 NAS 的服务端原始 Header。新增隔离代理改写 Host 的浏览器测试复现了相同的“页面来源不匹配”和空列表，修复前失败、修复后可初始化并保存。

## 修改

`dialog()` 先打开再构建，构建异常或异步失败显示错误及重试入口。初始化和保存期间禁止重复提交；取消会使会话失效，迟到的加载结果不能污染后续弹窗，异步读取表单被取消后也不会继续提交。

本地弹窗主动读取最新管理数据，不依赖此前缓存是否初始化。加载时显示状态，成功后列出后端返回的私有及授权根目录。目录读取失败可重试、切换根目录或关闭；失败或尚未完成时禁止保存。目录响应携带本次请求序号，旧响应不能覆盖新选择。目录名称使用 `textContent`，没有绝对路径输入入口。

管理页新增状态区域；即使首页初始化或管理请求失败，也能在数据源页看到原因。弹窗补充可访问性名称，授权根和子目录选择器补充标签。

来源兼容仅作用于引导读取：合法 HTTP(S) Origin 与 Host 域名不同时，必须同时收到浏览器同源 fetch 元数据 `Sec-Fetch-Site: same-origin` 和 `Sec-Fetch-Mode: cors` 或 `same-origin`。拒绝跨站、同站跨源及不匹配的 Origin Header；不使用 `Forwarded` 或 `X-Forwarded-*` 作为授权依据。缺少元数据的旧客户端仍须匹配 Host 域名。token 继续按管理员身份和**完整 Origin（含协议、端口）**隔离，所有写请求仍检查管理员、私有 Socket、CSRF、完整 Origin 和版本。

Socket 内 Header 的残余信任边界不变：root 和包用户本就可连接或修改应用，不能将这些 Header 视为能抵抗上述主体伪造的认证。没有扩大 Socket/文件权限，也没有修改 fnOS ACL。

`catalog.mjs` 和 `/api/directories` 的安全实现未改：保存仍由后端解析相对路径、打开授权根和真实目录、记录目录身份；已绑定连接更改仍验证历史，后续访问仍核对身份。Sync v2、持久化 schema 和备份格式均未改变。

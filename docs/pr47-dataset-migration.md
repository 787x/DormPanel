# PR47：Sync v2 安全换库与旧库退役

基线为已合并 PR46 的 main `d2f983e`。候选版本为 FPK **0.6.0**、Android **0.1.4**（X08E code 8，Phone code 6）。不修改 applicationId、Room schema 4、DPC2 / DPSS/1 字节格式或 256 提交上限；没有自动删除、原地压缩、Root 或 ADB 运行时依赖。

## 管理员操作

1. 在 FPK「历史与版本」检查并同步旧库，解决本地修改、待确认 PUT、冲突、异常路径及备份恢复。使用 PR46 功能生成完整归档及独立精简候选。
2. 在「数据源管理」添加指向候选父目录的**独立 WebDAV 连接**，填写 Android 实际使用的 URL 和凭据，不为该连接预建工作区。新旧目录、数据集必须不同。FPK 将经这个地址实际列举及 GET 全图，不能用 NAS 本地可读代替网络可达。
3. 回到「迁移到精简数据集」，选择授权根、候选相对目录与目标连接。后端重读源图、归档完成标记 / 原始字节 / SHA-256 / DAG、候选标记 / 单根 / 全部业务状态，并再次复查源。候选准备后任何合法旧提交，即使业务内容相同，也会使候选过期。
4. 准备成功即持久保护旧工作区。登记全部已知设备及 Writer，并人工确认停写。页面显示实际观察到的 Writer ID，但这既不是自动设备发现，也不能证明未知客户端或安装副本不存在。输入旧 datasetId 启用停写阶段。
5. 输入新 datasetId 切换 FPK。服务创建固定身份的独立新工作区，保留安装 writerId；原工作区的课程、缓存、检查点、绑定及历史完整保留。新旧工作区继续停写。
6. X08E、Phone 均从共享课表设置进入「更换共享课表数据集 / 恢复换库」。填写新共享父目录及新 datasetId。使用本机现有 WebDAV 账号、同一服务地址下的新目录；迁移不会修改账号或凭据。查看新旧身份、完整业务集合摘要和 Writer 后确认切换。本机已绑定数据不需要清空。
7. Android 切换后仍保持暂停；关闭窗口或重启可从同一入口恢复目录设置、继续确认。全部登记客户端已到达新库并核对后，由管理员允许各 Android 完成本机验收、恢复同步，再在 FPK 填写每台设备的本机结果记录，输入旧 datasetId 标记退役并开放新工作区写入。验收阶段不要插入日常编辑，以免使尚未完成的预览过期。
8. 新库正常编辑 / 同步。旧工作区保持只读，可查看历史和迁移证据。退役后「重新检查」仍核验旧图、完整归档及新库合法后续提交。旧图变化会转入「需要重新检查」，不会跨 dataset 自动合并。

管理员确认、FPK 后端实际验证、Android 本机结果是不同来源。FPK 清单中的 Android 结果由管理员核对填写，不是网络设备证明。界面没有声称已自动发现或验证全部客户端，也不把离线、没有新提交或勾选完成解释为永久停写。

## FPK 持久化与保护

`dataset-migrations.json` 是独立原子日志，包含源工作区完整恢复帧、源哈希及前沿、实际观察到的 Writer、候选 / 归档身份、固定新工作区 ID、设备登记及失败原因。它不改写 PR46 的 `verified.json`，也不修改任何旧 DPC。

阶段为 `prepared → frozen → switching → switched → retired`；`needs-recheck` 保留此前阶段和失败原因，恢复相同合法输入后可继续。`switching` 意图先落盘，新工作区和 catalog 后提交；重启复用同一目标 ID，不创建第二份绑定。取消保留两库和恢复证据，解除源保护，已创建的目标工作区保持只读；管理员可切回原工作区。新库开放日常编辑后不能简单取消反向覆盖。

保护同时位于 Workspace 事务、stage、同步发布 / 冲突决策入口和 Catalog 配置管理层。旧工作区不能经网页 API、普通同步、回退、导入确认、端点替换或重试发布。历史观察仍可持久保存新路径及已知哈希，危险操作失败不会遗忘漏列路径。备份可以包含迁移证据；存在迁移 / 退役保护时禁止用旧应用备份覆盖证据。

所有迁移 POST 复用私有 Socket 管理员鉴权、Origin / CSRF、请求 revision、catalog revision、活动工作区和授权目录校验。迁移与历史写操作、网络、配置及备份恢复互斥。前端不能用“完成”字段绕过源 / 目标重读。

## Android 中断恢复

保护存于现有 Room 检查点表，无破坏性 schema 升级：

| 记录 | 含义 |
| --- | --- |
| 203 | 网络预检前持久化暂停，保存原目录、目标目录及预期 datasetId |
| 202 | 按连接身份保存预检 / 迁移观察路径，后续漏列仍回查；取消预检将源路径并入原异常清单 |
| 200 | 完整已验证源 / 目标预览、原 Writer、原 / 新目录及 `prepared` / `committed` 阶段 |
| 204 | 上次 Android 本机验收或取消结果，重启后可从换库入口查看并供管理员登记 |
| ≥1000 | 独立不可变恢复 Blob、SHA-256 清单和完成 / 取消记录 |

预检前检查本地已发布、无 pending / attempted / conflict / abandoned / unverifiable、无旧 v1 未恢复状态。源验证从全部 witness 和 frontier 开始，目标使用首次绑定的有界全图验证器，但**不调用首次绑定写接口**。新根和源的全部业务字段及稳定身份必须等价；数量或名称相同不够。

准备事务保存原课程完整快照、所有原活动检查点、基线 / frontier / witness / 异常 / 绑定身份、原目录及目标完整根。恢复 Blob 逐个保存，清单记录真实 SHA-256，避免将所有旧数据反复 base64 拼接成巨大 JSON，也避免每次迁移加载全部历史恢复档案。保护查询只查存在性，不解码完整课程。

确认前重新验证两库。提交在一个 Room 事务中更新新 baseline、frontier、独立 witness、目录绑定指纹、学期目录身份和日志阶段；课程业务行原位保留，writerId 不变，旧 witness 不混入新库。

Room 提交后才写 SharedPreferences 的新目录。两者**不假定跨存储原子性**：日志在目录写入前后一直存在，同步核心和持久 Job 均拒绝执行；重启后可以幂等重写新目录并继续。最后完整重读源与新根、核对本机状态，再保存完成记录并解除暂停。进程无论在哪个阶段终止，都不会以新 URL 配旧 checkpoint 同步。

取消未完成预检或已验证的准备阶段可以恢复原同步；切换后的恢复方向是完成目标配置及验收，不反向覆盖原库。目标有独立新编辑时先保护新的提交和状态，由管理员处理，不能把它自动合回旧 dataset。

## 退役和人工清理

“完成换库”“管理员确认设备迁移”“旧目录在服务端不可写”“已物理回收空间”必须分别判断。本 PR 只提供前两项的流程与证据；应用内旧工作区只读不等于 WebDAV 服务端禁止其他客户端 PUT。

页面展示旧 / 新提交数量、旧 DPC 原始字节的可回收估算及实际已回收 **0 字节**。估算不包含必须保留的独立安全归档，也不保证文件系统块分配、快照或回收站已经释放。

只有全部客户端迁移并验收、NAS 管理员在存储或服务端落实源目录不再可写、完整归档复制到独立安全位置并重新验证之后，管理员才能在 fnOS 文件管理器手工处理明确的旧目录。先保存迁移日志和全部哈希，逐项核对旧目录 / 归档 / 新库的身份；保留可恢复副本及 fnOS 回收站 / 快照策略。应用不执行真实目录批量 DELETE，也没有基于时间或“最近在线”的自动清理入口。

NAS ACL 必须同时满足归档保护和 WebDAV 授权读取。无法达到受保护目录权限或无法通过 Android 使用的地址读取候选时，流程拒绝继续，不能悄悄放宽权限。本次真实网络测试仅在新建的隔离目录处理其继承 ACL，没有更改用户父目录授权或已安装应用数据。

实际执行的测试、产物和未验证范围见 [验收记录](pr47-dataset-migration-verification.md)。

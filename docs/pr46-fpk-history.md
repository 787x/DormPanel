# PR46：FPK 历史、回退与非破坏性精简准备（0.5.0 候选）

基线为已合并 PR45 的 `b6b962c`。不修改 Android APK、Sync v2 协议、业务持久化 schema 或远端提交格式，不合并、打 tag 或发布 Release。

## 使用与语义

页面新增独立「历史与版本」。默认读取经过完整闭包验证的本地缓存，明确显示缓存、异常、待发布、当前课程关联和多前沿。管理员主动点击「重新检查远端历史」才进行网络读取，没有后台扫描或轮询。

历史按父子因果层次排列，显示分叉、合并、父版本及课程变化摘要。DPSS 固定时间、WebDAV mtime 和首次观察时间均不作为提交时间。完整 ID、Writer、父引用与 SHA-256 放在高级详情；多 tips 不会折叠成一个“唯一最新”。容量展示为已验证提交数 / 256 与原始 DPC 字节数，230 起提示容量风险。

选择任意已验证版本可以按业务集合分页查看完整快照的只读卡片及字段。两个版本的比较使用协议稳定身份：本地课程、事件、来源、原始实例、全周 / 指定周覆盖、日期调整、学期阶段 / 节次、自定义学期身份全部参与。相同名称不视作相同记录；来源、关联实例和覆盖共享关联组，展示学期关联。每次返回至多 40 条差异或快照记录，包含完整前后字段；大变更按需继续展开。回退预览中的新增表示相对当前重新引入目标历史记录，即恢复该业务身份。

回退把选中完整快照作为目标，以**当前完整已验证前沿**为父创建一个新 DPC2。等价多 tips 可以作为全部父；状态有分歧的分支、冲突、未发布修改、待确认上传、恢复异常、暂不可验证路径和满容量均禁止回退。相同状态不创建提交。回退不使用清空数据库或重置工作区。

预览 token 最多 8 个、有效期 10 分钟，绑定管理员、活动工作区、catalog 版本、完整工作区帧、dataset、目标原始字节及图哈希 / tips。确认文本与目标必须一致；确认重新从远端完整校验，任一输入变化都拒绝旧操作。预览差异也可分页，token 不跨工作区复用。

新候选通过原 `Workspace.tx → stage → SyncEngine.publish` 保存 capture、精确字节、attempt、回执与本地重放。失败保留原协议的候选和恢复信息；回执丢失后重启可精确回读。发布后再次观察远端，不能阻止最后一次检查之后另一 Writer 的并发 PUT；出现的新分支仍由现有 Sync v2 处理。

## 完整历史归档

这是完整远端 DPC 历史归档，**区别于现有加密 FPK 应用状态备份**：不包含应用凭据、本地未发布状态或其他数据集。原有加密备份格式仍为 version 1，继续接受 0.4.0–0.4.4，并接受新 0.5.0 元数据。

管理员选择 fnOS 授权根及现有相对目录。服务新建不可覆盖的 `history-UUID/`，内部复制原始 `dormpanel-sync-v2/commit-ID.dpc`，从不写旧库。拒绝 private 导出根、未授权根、路径穿越、符号链接以及任何位于活跃 `dormpanel-sync-v2/` 内的目标（包括授权根本身位于协议目录的情况）。

目录使用并反复验证 0700，DPC 位于受保护目录内，清单 0600；通过 O_NOFOLLOW、目录 inode 身份、文件类型 / 大小、排他 hard link 和 fsync 防止覆盖与链接替换。仅使用既有支持的 Linux 本地文件系统发布能力，目标至少保留 80 MiB 可用空间。归档未加密，依赖 NAS 授权与受保护目录，管理员应妥善保管磁盘和授权。

写入后使用独立读取适配器逐文件读取、验证 SHA-256 / 原始字节、身份、父闭包并重建 DAG。`verified.json` 保存 dataset、全部 ID / SHA-256 / 父关系、tips、范围与验证结果；只有完整回读和最终源检查通过后，才从已回读的私有暂存文件排他发布此标记。无标记目录一律视作未完成，不能当成有效归档；中断不删除源文件，也不自动清理输出。

单图仍最多 256 提交、32 MiB 原始输入、64 tips / parents，所有原协议校验不放宽。复制、归档回读、最终源复查使用独立有界 I/O 阶段，以免把 256 提交的合法图误判成单次请求预算超限。缓存仍可在后续网络失败时只读显示上一次完整验证的闭包，异常明确阻止危险写入。

## 精简候选与后续迁移

「归档并准备独立精简候选」先执行上述完整归档与可恢复性回读，再在另一个新建 `compact-UUID/` 中创建新 datasetId、无父的完整根。所有课程、来源、实例、覆盖、学期及业务身份均保留，只有外层数据集 / 提交身份为新值。

候选独立回读重建图，要求恰好一个根，使用协议 `stateBytes` 对所有业务集合逐字段等价校验。结束前重新完整读取源图，并比较工作区帧 / catalog / dataset / 全部哈希 / tips；源变化或新分支均不发布候选有效标记。候选清单明确 `migrated: false`，保存来源、归档位置与逐台切换说明。

这一阶段**只准备候选**，没有切换任何现有 FPK 或 Android，也没有清理旧库。FPK 可以由管理员另建连接和新工作区后明确接收候选；既有 Android 的保留状态换库需要后续独立迁移流程，不指导清空数据库或修改已确认哈希绕过身份验证。

真正退役与磁盘回收必须由管理员登记全部客户端 / Writer、明确停写、迁移并逐台验收，检查旧库没有新增分支。协议无法自动证明全体 Writer 已退役。不得按时间、大小、Writer 或当前 tips 推断可删除提交，不提供活跃目录 GC、批量 DELETE、最近 N 份保留或一键清理。

## 安全边界与验证

历史读取仍要求私有 Socket 管理员身份和明确活动工作区；默认只返回有界摘要，不把原始图或 locator 发给浏览器。写操作沿用 Origin / CSRF、工作区版本、catalog 版本、当前工作区与数据集校验；历史操作期间阻止其他写入，并与现有网络、配置和备份恢复互斥。

可复现：`npm test`、`npm run test:frontend`、`npm run check`、`npm run build`。Linux 专用权限与归档测试需在 Linux 的非 root 包用户下运行。`node scripts/history-vectors.mjs` 使用真实回退链路生成合成 DPC2，供 `:schedule-core:testDebugUnitTest --tests '*AppendOnlyScheduleSyncTest' --tests '*FnosWriterParityTest'` 验证未修改的 Android 核心。

验证结果、候选哈希与边界见 [本次验收记录](pr46-fpk-history-verification.md)。

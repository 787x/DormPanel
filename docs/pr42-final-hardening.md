## 解密预览的生命周期

预览仍默认有效十五分钟。新增一个 `unref` 的最早到期定时器，过期即撤销令牌并将目录交给清理队列，不再依赖用户再次验证或重启。没有预览、没有待清理项目时没有定时器；只有真实清理失败才默认延迟六十秒重试，不持续扫描空闲目录。

取消恢复通过同样受管理员、CSRF、同源和 catalog revision 约束的 cancel API 撤销当前管理员的指定预览。页面取消确认时调用该接口；关闭页面或放弃操作则由到期定时器处理。目录删除是异步清理，权限失败时不会恢复令牌或放宽 0700/0600 权限，队列继续保留所有权并重试。正常关服也撤销未使用的预览、清理可删除暂存；失败残留可在启动时重新处理。

验证后的外部依赖检查、状态戳读取或注册令牌失败时，已经认证解密的暂存仍由 finally 交给清理队列；认证失败、句柄关闭及暂存目录创建后的 fsync 失败也有明确的清理所有权。删除后 fsync 私有父目录，失败同样保留重试。

清理任务与维护操作互斥：维护栅栏先阻止新的清理任务，并等待已开始的清理结束后才使用预览。恢复使用中越过到期时间不会删除输入；事务结束后再处理到期项目。已提交恢复中断后停止运行期清理，由原启动恢复流程接管。

每次清理核对磁盘上的恢复日志 stage/old、最近一次成功恢复前快照，以及仍有效的预览。引用无法读取时不猜测删除；日志输入及旧快照不得因为令牌过期而被删除。恢复成功后释放所有预览，保留最近一次恢复前快照。DPBK0001、KDF、密文布局、清单及恢复决策协议没有改变。

## 并发启动与 Socket

生产 `main.sh` 改为由启动父 shell 先取得 fd 9 的排他 flock，再检查或清理 PID/Socket/ready、写日志、启动 Node 和发布 PID。Node 继承同一个 fd 持锁，父 shell 的失败清理同样在锁内。

失败方在另一个启动尚未 ready 时只返回失败，不删除或覆盖任何运行文件。已运行实例通过 PID/Socket/ready 判断后，仅复验原有私有访问权限；权限不合法或 Socket 为符号链接时返回失败，仍不清理对方的文件。正常实例的 PID、Socket inode、ready 和日志保持。

stop 捕获并只终止原目标 PID，不在等待过程中跟随可能变化的 PID 文件。退出后必须再取得锁才能清理陈旧文件；若另一个 start 已获锁，则失败返回并保留新实例的文件。异常退出后锁由内核释放，下一位持锁者才能删除陈旧 Socket 并重建。没有外部锁服务、新依赖、Root 运行或权限边界变更。

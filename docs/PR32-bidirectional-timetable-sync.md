# PR32 — WebDAV 课表双向同步

基于已合并的 PR31。X08E 与手机现在都可编辑、导入、替换、删除课程、重置全部/指定周次编辑、修改日期调整和学期配置。普通本地课表仍可离线使用。没有修改 applicationId、版本、签名、X08E 横屏、原生服务、自启策略或 HA 自定义集成。

## 持久化与原位升级

保留 `schedule.db`、Room v4 和既有 v1→v2→v3→v4 migration；不需要新增表或破坏性迁移。原 `schedule_sync_checkpoint` 继续保存有界 v1 快照，按固定 id 区分本地同步元数据：

| id | 内容 |
| --- | --- |
| 1 | 上次确认同步的完整共同基线，沿用 PR31 checkpoint |
| 2 | 当前本地完整学期 catalog 与自定义覆盖键；快照中的课程集合为空 |
| 3 | 未处理冲突的完整远端快照 |
| 4 | 结果未确认的完整候选发布 |
| 5 | 该次发布计算时的精确本地状态，供上传期间的新编辑重放 |
| 6 / 7 | 历史核实的 head 与已验证游标，支持跨进程分段继续 |

当前课程、事件、来源、实例、日期调整和稀疏编辑仍以各 Room 表为准。待上传状态由这些记录及当前 catalog 与共同基线的内容差异计算，不依赖内存 dirty flag。完整快照中的记录缺失表示删除或重置；保留基线即可区分删除与从未存在，无需按时间戳猜测。

PR31 手机的 id=1 直接成为共同基线；没有 id=2 时读取原 checkpoint catalog，并按需建立独立 catalog。旧课程、revision、sourceId、seriesId、实例身份、编辑、自定义覆盖键与加密账号均保留，无需重新绑定。

PR31 X08E 没有 Room 基线时，按原设置中的 datasetId、已发布 revision/generation 及待确认 hash 核实远端历史链。**当前本地课程不会被当作旧已发布状态**：它与已验证历史快照之间的差异作为本地修改，随后与最新远端合并。历史缺失、损坏或身份不符时拒绝自动升级，保留数据；应恢复共享目录中的历史快照或修正账号/目录，再继续同步。PR31 第一次发布未激活 head 时，仍保留原 datasetId，通过条件创建恢复。

绑定后学期修改在 Room 中提交，不向旧偏好镜像。首次建立 catalog 与未绑定时的配置写入也由 Store 串行处理。无预设的自定义学期仍有关联来源时，会提示先移除来源再删除学期；恢复内置预设可以直接同步。

## 合并与冲突

三方输入为共同基线、当前本地、已验证远端。按事件 id、本地课程 id、日期、编辑 key、学期 key 合并；同一导入来源的元数据与原始实例作为一个完整替换单位，稀疏编辑独立合并。两个设备改同一来源下不同课程的编辑可以自动保留双方结果。导入时间仅是附属元数据，完全相同的替换不会因为导入时间不同而冲突；课程内容不采用 Last Writer Wins。

相同修改合并一次；仅一侧修改采用该侧；两侧不兼容修改保留冲突。`null` 继承、空字符串显式清空、缺少编辑记录表示重置，三者保持不同。来源/本地课程删除与子编辑、学期变化与关联来源/编辑采用关联冲突单位，避免悬空引用。学期关联判断有意保守，同一编辑记录内的不同字段也可能要求用户选择。

存在冲突时不发布合并结果、不修改本地课程或共同基线；完整远端保存在 id=3。两端共享管理页中的“查看 / 处理同步冲突”展示课程/配置及本地、远端摘要。可暂不处理，或对列出的冲突统一选择保留本地/采用远端。选择仅影响冲突及必要关联记录，独立修改仍自动合并；结果与新的基线在一个 Room 事务保存。随后重新读取远端，若其再次变化，重新比较并可能再次要求处理。没有强制覆盖按钮。

## 发布、自动同步与故障恢复

网络协议仍为 PR31 v1：不可变 `snapshot-<revision>.dps`、`dormpanel-head-v1`、强 ETag、条件 PUT、探测服务器条件写能力、快照与指针回读校验、同源/认证/大小/超时限制。PR31 v1 读者仍可读取新发布内容；没有新增服务器要求或在快照中携带认证。

每次发布基于刚读取的远端 revision/ETag，并先保存候选及其精确本地 capture。409/412 后读取新 head，核实原候选是否已提交，重新合并当前本地修改；不无条件重传旧快照。每次运行的收敛轮数有界。若其他设备已在未确认候选之后发布，通过历史链确认回执，再重放 capture 之后的新编辑。历史检查每轮最多遍历 256 个版本，保存游标后可继续，不需要清空数据。历史文件与探测文件均不自动删除。

Room 合并、校验、课程替换、catalog 和基线更新在事务中完成；网络期间不持有事务。可见页面仅在事务整合及重载的短窗口暂停写入，上传期间仍允许本地编辑。保存失败会保留错误提示；本地保存不表示云端同步成功。

两端进入/恢复前台检查远端；本地提交后合并安排同步，前台约 1.5 秒去抖。原生 JobScheduler 提供持久化、网络约束的一次性任务及指数退避；故障连续自动重试有界，之后提示手动检查，新的编辑或前台检查可重新触发。无固定周期轮询、永久服务或持续动画。Android force-stop 期间系统不会执行应用任务，重新打开后从 Room 恢复。OEM 后台调度不保证准时。

页面区分已同步、待上传、同步中、离线/重试、冲突、失败及超过 24 小时未验证的过期状态。手机管理页保留新增、导入、替换、删除和学期设置；X08E 保留原 Sources 共享管理入口。复杂冲突详情留在二级对话框。

